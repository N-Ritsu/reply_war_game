# 遊び方(手元)と公開の手順

## 1. 手元で遊ぶ
`index.html` をブラウザで開くだけで動く。静的サーバーで開く場合は、プロジェクトのフォルダで次を実行して、`http://localhost:8000` を開く。

```bash
python3 -m http.server 8000
```

## 2. 仕組みのテスト

```bash
node tests/run.js           # ルール全般と、対戦のルール(695項目)
node scripts/pvp-sim.js 100 # 対戦のバランスの自動対戦(任意)
```

サーバーの通し確認は、下の「案C」を参照。

## 3. 配布用フォルダを作る

```bash
./scripts/build.sh
```

`public/` ができる(`index.html`・`css/`・`js/` をフォルダごとコピーし、`index.html` が参照するファイルが全部あるかを確かめる)。新しい `js` ファイルを足したときも、一覧の直し不要。

## 4. 公開する(ユーザーの作業)
公開は、本番に関わる作業なので、ユーザーが実行する(前回の教訓 1-2)。私はコマンドと、実行後に確かめることだけを書く。**以下は、まだ試していない案**。

### 案A: Cloudflare Pages(直接アップロード)
前回と同じ Cloudflare を使える。サーバーを持たない静的ファイルだけなので、無料枠の心配は小さい。

1. Cloudflare のダッシュボードで、Pages のプロジェクトを作る(名前は、運営者の名前に合わせて決める)。
2. `./scripts/build.sh` で `public/` を作る。
3. 次のコマンドを実行する。

```bash
npx wrangler pages deploy public --project-name <プロジェクト名>
```

4. 出てきた URL を開き、確認する(下の「公開後に確かめること」)。

### 案B: GitHub Pages
GitHub のリポジトリには、文書(`docs/`)だけを送る運用なので、このままでは使えない。使うなら、公開用に別のリポジトリを作り、`public/` の中身を送る。

### 案C: Cloudflare Workers(対戦サーバー込み。プレイヤー対戦を使うなら、こちら)
対戦(レート戦)には、サーバーが要る。ゲームの画面も、同じ Worker から配るので、**設定なしでつながる**(案A・Bは、対戦なしの静的な公開)。
**まだ、本物の Cloudflare では試していない**(ローカルの `wrangler dev --local` での確認だけ)。以下は、ユーザーの作業。

```bash
# 1. 道具を入れる(初回だけ)
cd server && npm install

# 2. Cloudflare にログインする(ブラウザが開く)
npx wrangler login

# 3. データベース(D1)を作る。表示される database_id を、server/wrangler.toml の database_id に貼る
npx wrangler d1 create reply-war-game

# 4. 表を作る(本番)
npm run db:remote

# 5. 画面の配布用フォルダを作ってから、公開する(ルールの取り込みも自動)
cd .. && ./scripts/build.sh
cd server && npm run deploy
```

公開後、表示された URL(`https://reply-war-game.<あなたのアカウント>.workers.dev`)で、次を確かめる。
1. タイトルから「対戦(プレイヤー)」を開き、「<名前> レート 1500」と出る(サーバーの自動検出と接続ができている)。
2. 「練習で対戦」(ボット戦)が遊べる。
3. 別のブラウザ(または、スマホ)から、同じ URL で「レート戦を探す」を押し、**2人で組まれて、対戦できる**。終わったあと、レートが動く。
4. 「ランキング」に、2人が出る。

そのあとの設定:
- **接続元の制限**: `server/wrangler.toml` の `ALLOWED_ORIGINS` に、公開した画面の URL(例 `https://reply-war-game.xxx.workers.dev`)を書いて、もう一度 `npm run deploy` する。
- **画面を別の場所で配る**(Cloudflare Pages など): `wrangler.toml` の `[assets]` を消し、`js/config.js` の `server` に Worker の URL を書き、`ALLOWED_ORIGINS` に画面の URL を書く。
- **ボットが付くまでの待ち時間**: `wrangler.toml` の `FILL_WAIT_MS`(ミリ秒。初期値 5000)。
- **記録をもとにしたボット**(2026-11-08): 同じくらいのレートの人の動きに似せたボットが、5秒で相手をする。**新しい表 `match_stats`・`last_ghost` が要る**ので、すでに公開している場合は、**`npm run db:remote` をもう一度**実行してから、`npm run deploy` する(表がないと、記録はされず、標準のボットになるだけで、対戦は動く)。記録のある人が1人もいないと、標準のボット(レートなし)になる(最低の試合数は `GHOST_MIN_MATCHES` で変えられる。初期値 1)。**画面には、ボットとは出ない**(本物の人と同じ形で、名前とレートが出る)。
- 無料枠・料金は、公式のページで確かめる(私は最新の条件を確かめていない)。

ローカルで、サーバーごと確かめる場合:
```bash
cd server && npm run db:local && npm run dev   # → http://localhost:8787 を開く(画面もここから配られる)
npm test                                        # 別の端末で。サーバーの通し確認(70項目)
# 広告・回数制限・広告削除の確認(86項目)は、`npm run dev` の代わりに `npm run dev:ads` で起動してから `npm test`
```

### 広告を付けるとき
**公開の前に**: `legal/` の、赤字の `【…を記入】`(運営者の氏名・住所・電話番号・メールアドレス・公開日)を、書く。
広告は、初期状態では**無効**。有効にする手順(審査・決済の用意・設定・新しい表の作成)と、気をつけることは、[広告の設計.md](広告の設計.md)。

### 公開の前に: 効果音の規約
効果音の一部は、**効果音ラボ**の素材(`js/sfxdata.js` に埋め込み)。規約は予告なく変わるので、**公開の前に、もう一度、規約ページ(https://soundeffect-lab.info/agreement/)を確認する**。素材の試聴ページ(`out/demo/`)は、公開しない。詳しくは [効果音の素材.md](効果音の素材.md)。

## 5. 公開後に確かめること
- タイトルが出て、「遊び方」が開く。
- 爽快モードで、1戦を最後まで遊べる(論破か敗北の演出が出る)。
- リアルモードで、ローマ字を打てる。
- 音が鳴る(私は聞こえ方を確かめられていないので、ここはユーザーの耳で)。
- スマホで開き、爽快モードが遊べる。
- ブラウザを閉じて開き直しても、クリアの記録が残る。

## 6. セキュリティの見出し(CSP)
`index.html` には書いていない(`file://` で動かすため)。公開するときは、配信側の設定で付ける。

```
Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; base-uri 'none'; frame-ancestors 'none'
```

`style-src` の `'unsafe-inline'` は、NPC の SVG に付けた色の指定のため。外のファイル(フォントなど)を足すときは、ここも直す(前回の教訓 4)。

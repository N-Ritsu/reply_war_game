# プレイヤー対戦(レート戦)の設計

2026-11-06 に、ユーザーの依頼で追加した。NPC 戦は、そのまま残している。
このメモは、決まったこと(ユーザー)・私が決めたこと・仕組み・サーバーの構成・通信・限界・未確認をまとめる。

## 1. ユーザーが決めたこと
| 項目 | 内容 |
|---|---|
| 隙みせ攻撃 | NPC 戦での「NPC のレス」を、**隙みせ攻撃**と呼ぶ。対戦では、**プレイヤーも隙みせ攻撃を打つ**。 |
| 攻撃と隙みせ | **攻撃 → 相手のメンタルにダメージ**。**隙みせ攻撃 → 自分のスレの盛り上がりが上がる**。 |
| 盛り上がり | 時間で減る。**定期的に隙みせ攻撃を打つ**必要がある。 |
| 連投の制限 | 隙みせ攻撃は、**1回打ったら2秒以上あけないと次を打てない**。 |
| 種類 | 長文・感情論・ブーメラン・論点ずらし・短文連打の**5種類から選ぶ**。 |
| モード | **爽快でもリアルでも**対戦できる。**リアルの使用者のほうが、ダメージを大きく**調整する。リアルでも、隙みせ攻撃は**選んでクリックで送信**できる。 |
| 勝負の形 | **レート式**。 |
| 通信の基盤 | **Cloudflare Workers に合わせたい**(リアルタイム通信に不向きなら、私のおすすめで)。→ Workers + Durable Objects(WebSocket)+ D1 が向いているので、これにした。 |
| 盛り上がりの役目 | **各自の盛り上がりが、自分の攻撃ダメージの倍率になる**。 |
| 相手の探し方 | **ランダムマッチ(レートの近い人)**。 |

## 2. ルール(`js/pvp.js`。ブラウザとサーバーで同じファイルを動かす)

### 2-1. 流れ
1. 双方、メンタル 500・盛り上がり **60** で始まる。
2. 隙みせ攻撃(5種類から選ぶ。**同じ種類は、2連続では打てない**)を打つと、自分の盛り上がりが +20(上限100)。その隙みせは、相手が返せる**的**として、スレに載る。
3. 相手は、その隙みせの種類に**効く言葉**で攻撃する(NPC 戦と同じ、特攻のカード)。当たると、こちらのメンタルが減る。
4. 先に相手のメンタルを 0 にしたら勝ち。**自分の盛り上がりが 0 になったら、その時点で負け**。**3分**で決まらなければ、メンタルの残りの割合が多い方が勝ち(ほぼ同じなら引き分け)。
5. 盛り上がりが **40 を切る**と、ゲージが**赤く震える**。**20 を切る**と、**画面全体が赤く震え**、ゲージと隙みせ攻撃のボタンが強調され、「隙みせを打て！」が出る(自分の盛り上がりだけ。相手のゲージは、赤くなるだけ)。

### 2-3. 私が決めたこと(依頼になかった部分)
- **膠着の防止**(2026-11-08 に変更): 両者が隙みせを打たないと、的がなく、攻撃もできず、膠着する。最初は「盛り上がりが 0 のあいだ、メンタルが減る」にしていたが、ユーザーの指示で、**盛り上がりが 0 になった時点で負け**に変えた。誰も打たなくても、開始から約20秒で決着する(両者が同時なら、メンタルの残りで。同じなら引き分け)。開始の盛り上がりは、40 だと、始まった瞬間に 40 を切って赤くなるので、**60**にした。
- **外れの代償**: 攻撃には的が要り、外れると自分が減る。当てずっぽうの連打が得にならないようにするため。詰め(追加ダメージ)は、対戦では入れていない(自分の外れだけで十分、と判断)。
- **対戦で使える言葉**: いなす・待たせ煽り・自演乙は除いた。相手の入力待ちという状態が、対戦にはなく、いなすは役目がないため。
- **時間切れ・同時決着**: 3分で打ち切り。同時に 0 なら、残りが多い方。
- **隙みせの文面**: 種類ごとに3〜6本、固定の文を用意した(`BAIT_LINES`)。自由入力にはしていない(悪用・不適切な文を避けるため)。
- **レートのつけ方・ボット補充**: 下の 3。
- **爽快とリアルの混合**: 同じレートの表で、モードを問わず組む。強さの差は、ダメージ倍率で調整した(2-4)。

### 2-4. バランス(自動対戦。`node scripts/pvp-sim.js` / `tests/pvp.js`)
ボット(腕前を決めた自動プレイ)同士を、席を入れ替えて50〜100試合ずつ戦わせた。
| 組み合わせ | 結果 |
|---|---|
| 爽快の常連 vs 爽快の初心者 | 常連の勝率 約85%(約60秒) |
| リアルのタイパー(打つのが2.2字/秒)vs 爽快の常連 | タイパーの勝率 約50〜58%(約50秒) → **ほぼ互角** |
| リアルの古参(3.2字/秒)vs タイパー | 古参の勝率 約58% |
- 1試合は**約1分**。腕前の差が勝敗に出て、普通の速さのリアルは、爽快の常連と互角になるよう、リアルのダメージ倍率(**1.1**)を選んだ。
- **2026-11-08 の再調整**: 「同じ種類の連続禁止」を入れたら、隙みせの種類が毎回変わり、打ち込んでいる間に的が消えやすくなった。それまでのボットは、的が消えても、決めた言葉を最後まで撃って外していた(人間は、打ち直す)ため、リアルが不当に弱く出て、タイパーの勝率が 6% に落ちていた。**ボットを、的が消えたら送らずに打ち直す作りにした**ら、今度はリアルが強くなりすぎた(76%)ので、リアルの倍率を 1.35 → 1.1 にした。同種連続禁止そのものの影響は、リアルがやや不利(打ち直しが要るため)。
- 最初の版は、ボットが「打ち終わる前に発動する」作りで、リアルが99%勝つ結果になっていた。**ボットの作りの誤り**(人間は打ち終えてから発動する)で、ルールの問題ではなかった。直してから、数値を決めた。
- 盛り上がりの効きを弱くすると、隙みせを少なく打つ方が得になった(的を減らせるため)。0.3〜1.8倍にして、盛り上がりを保つ方が得になるようにした。

## 3. レート戦
- **Elo**。最初は1500。期待勝率 = 1 / (1 + 10^((相手 - 自分) / 400))。更新 = K × (結果 - 期待勝率)。結果は、勝ち1・引き分け0.5・負け0。**K は、20戦までは40、以降は24**。下限100。
- **マッチング**: ロビーに「探す」を送ると、**レートの差が、100 + 待った秒数 × 20 以内**の人と組む(待つほど広がる。双方の待ち時間のうち長い方を使う)。
- **ボット補充**: **25秒**待っても組めなければ、ボット(練習相手)が代わりになる。**レートは動かず、成績にも数えない**。ボットの強さは、本人のモードとレートで決める(爽快: 初心者 / 常連、リアル: タイパー / 古参)。
- **やめる・切断**: やめたら負け。切断は、**12秒以内に戻らなければ負け**(戻れば、そのまま続く)。部屋に相手が20秒来なければ、部屋を閉じる(レートは動かない)。
- **記録**: `players`(id・キーのハッシュ・名前・レート・戦績)と、`matches`(対戦ごとの結果と、レートの前後)を D1 に保存する(`server/schema.sql`)。

## 4. 構成
```
ブラウザ(js/pvpui.js 画面 / js/net.js 通信)
   │  WebSocket(JSON)
   ▼
Worker(server/src/index.js)── /ws/lobby ──▶ Lobby(Durable Object。全員で1つ)  名前・レートの確認、相手探し、部屋づくり
   │                       └─ /ws/room/<id> ▶ Room(Durable Object。対戦ごと)   ルール(PvP)を動かす・状態を配る・レート更新
   ├─ /api/ranking ─────────────────────────▶ D1(players / matches)
   └─ それ以外 ─────────────────────────────▶ ゲームの画面(../public)
```
- **ルールは1か所**: `js/data.js`・`js/engine.js`・`js/pvp.js` を、`server/build-game.js` が1ファイル(`server/src/game.generated.js`)にまとめて、サーバーが読み込む。ブラウザは、同じ `js/pvp.js` を、ボット戦(練習)と、表示のための計算(どの言葉が効くか)に使う。
- **サーバーが判定する**: ブラウザは、操作(隙みせ・手札のスロット・打ち込んだ言葉の id)を送るだけ。ダメージ・手札の配り・時間・勝敗は、サーバーが決める。手札は、本人にしか送らない(相手の手札は見えない)。
- **ブラウザの画面は同じ形で描く**: 画面は、「自分から見た状態(`PvP.view`)」だけを見て描く。ボット戦(手元)も、オンラインも、同じ画面。時間は、サーバーから状態を受け取ってからの経過で補う(盛り上がりの減りや、期限のバーが滑らかに動く)。
- **画面の配り方**: `server/wrangler.toml` の `[assets]` で、Worker が `public/` も配る(同じ場所なので、設定なしでつながる。`/health` で、同じ場所の対戦サーバーを自動で見つける)。画面を別の場所で配るなら、`js/config.js` の `server` に Worker の URL を書く。

### 4-1. 通信(JSON。`server/src/lobby.js` / `room.js` / `js/net.js`)
| 向き | メッセージ | 内容 |
|---|---|---|
| → ロビー | `hello {id, secret, name}` | 端末のキーで本人確認。なければ新しく作る |
| ← | `welcome {id, secret, name, rating, games, wins, losses, draws}` | `id`/`secret` は、端末(localStorage)に保存する |
| → | `queue {mode, name}` / `cancel` / `rename {name}` | 相手探し |
| ← | `queued` / `found {room, token, slot, rated, bot, me, foe}` | 組まれた。部屋の番号と、自分専用のトークン |
| → 部屋 | `bait {type}` / `play {idx, typo}` / `free {id, typo}` / `reload {idx}` / `quit` / `ping` | 操作 |
| ← | `countdown {ms}` / `view {v, ev}` / `end {result, rating}` / `error {msg}` / `pong` | `view` は100msごとと、操作のたび。`ev` は出来事(隙みせ・攻撃・期限など)。隙みせが断られたときの理由は `cooldown`(2秒未満)/ `same`(同じ種類の連続)。終了の理由 `reason` は `mental` / `buzz`(盛り上がり切れ)/ `time` / `forfeit` |

## 5. 不正への備えと、限界
**備え(サーバーで実施)**
- 判定は、すべてサーバー。ダメージ・コンボ・手札は、ブラウザから送れない。
- 手札は本人にしか送らない。**爽快の人は、手札にないカードを使えない**(スロットの番号だけ送る)。
- モードと違う操作は無視する(リアルの人が手札で撃つ・爽快の人が言葉を直接送る)。
- **連打の抑制**: 1人の操作は、最短50msの間隔。**リアルの言葉は、その言葉を打つのに必要な時間(最大14字/秒)より速く送れない**(マクロ対策)。
- 本人確認: 端末ごとのキー(ランダム)の **SHA-256 だけ**を保存。キーが違うと別人になる(なりすましできない)。名前は、制御文字・`<>"&` を除いて12文字まで。
- 接続元の制限: `wrangler.toml` の `ALLOWED_ORIGINS` に、公開した画面の URL を書くと、それ以外からの接続を断る(空なら制限なし)。

**限界(やっていない・できないこと)**
- **アカウントはない**。端末のキー(ブラウザの保存)だけ。保存を消すとレートは別人になり、別の端末に引き継げない。メール・ログインは入れていない。
- **リアルモードで、打っている「ふり」をする自動化は、完全には防げない**(人間の速さの上限で送られたら、見分けられない)。
- **2つのアカウントで、わざと勝ち負けを渡す(レートの水増し)は防げない**。
- ランダムマッチなので、人が少ないと、25秒待ってボット戦になる。
- 名前は自由入力(不適切な名前の対策は、していない)。
- ロビーは Durable Object 1つ。同時に探す人が非常に多い場合は、分割が要る(想定していない)。

## 7. 未確認
- **本物の Cloudflare 環境での動作**。ローカルの `wrangler dev --local` での確認だけ。公開(ユーザーの作業)のあとに、`公開手順.md` の確認を。
- **料金・無料枠で足りるか**。Durable Objects(SQLite 型)と D1 は、無料のプランでも使えるはずだが、私の知識で、最新の条件は未確認。対戦中の Room は、状態を持つため、約1分のあいだ起きたままになる(時間課金)。
- **遅延(ラグ)の体感**。ローカルでは遅延がない。実際の通信では、操作が結果に反映されるまで、サーバーとの往復の分、遅れる。爽快の手札の入れ替わり(0.15秒)が、遅延が大きいと重く感じる可能性がある。
- **人が遊んでの、バランスと面白さ**。ボットの数字だけで決めた。盛り上がりの減り方(1秒に3)・開始の60・警告の40/20・リアルの倍率(1.1)は、遊んで調整が要るかもしれない(`PvP.CFG`)。
- **Cloudflare の公式のスキル(プラグイン)を使っていない**。導入を勧めたが、このセッションでは有効にならなかったため、公開されているドキュメントの知識で書いた(Durable Objects の WebSocket・D1・assets)。公開前に、プラグインを入れてのレビューをおすすめする。
- 実機のスマホでの操作感(隙みせのボタン・手札)。BGM・効果音の聞こえ方(対戦中は NPC 戦と同じ曲を流している)。

## 4. サーバーの公開(Cloudflare)
手順は `docs/公開手順.md` の案C。要点:
```bash
cd server && npm install                       # node_modules は、zip に入っていない
npx wrangler login                             # ユーザーが、ブラウザで許可する
npx wrangler d1 create reply-war-game          # 出てくる database_id を、server/wrangler.toml の database_id に書く
npm run db:remote                              # 表を作る(match_stats・last_ghost・daily_plays・entitlements・payments を含む)
cd .. && ./scripts/build.sh                    # public/ を作り直す(公開の前に、必ず)
cd server && npm run deploy                    # 公開(node build-game.js も、自動で動く)
```
- 公開後の確認: `<URL>/health` が `{"ok":true,…}`。タイトルから「オンライン対戦」を開いて、「<名前> レート 1500」と出る。**別のブラウザ(スマホ)**から「レート戦を探す」を押して、2人で組まれる。**1人で押すと、5〜6.6 秒で、CPU が相手になる**(正常)。
- **`server/wrangler.toml` の `ALLOWED_ORIGINS`** に、公開した URL(`https://…`・末尾スラッシュなし)を書いて、もう一度 `npm run deploy`(**確認が終わってから**。書き間違えると、全員、対戦に入れなくなる)。
- **`ADS_ENABLED = "0"` のまま**にする(広告・回数制限が、無効)。**`PAYMENT_MODE = "mock"` は、本番では、絶対に付けない**(買わずに、広告削除が付いてしまう)。
- `server/src/reference.generated.js` に、運営者のプレイから作った、CPU の基準(レート 1700 相当)が、すでに入っている。そのまま、一緒に公開される。
- **無料枠で足りるか**は、未確認。公開後に、Cloudflare の管理画面で、使用量(Durable Objects・D1)を見る。

## 6. 課金(広告削除 100円。Stripe)
- 設計: `docs/広告の設計.md`。コード: `server/src/pay.js`(`/api/status`・`/api/checkout`・`/api/stripe-webhook`)・`server/src/db.js`・`js/ads.js`(購入の画面)。
- **付与は、Stripe の署名つきの「支払い完了」の通知(Webhook)を、サーバーが受け取ったときだけ**。画面からは、付けられない。同じ通知が2回来ても、1回だけ反映。
- Stripe 側の用意(**ユーザーの作業。本人確認・口座・2段階認証があり、代行できない**): アカウント作成 → **最初は、テストモード** → Webhook の送り先を `https://<URL>/api/stripe-webhook`、イベントを `checkout.session.completed`(コンビニ払いなどを使うなら `checkout.session.async_payment_succeeded` も)→ 署名用の秘密(`whsec_…`)を控える。
- 秘密の値は、**ファイルに書かず**、ユーザーが、次のコマンドで入れる(**値を、チャットやログに、貼らない・表示させない**):
```bash
cd server
npx wrangler secret put STRIPE_SECRET_KEY        # sk_… (最初は、テスト用)
npx wrangler secret put STRIPE_WEBHOOK_SECRET    # whsec_…
```
- 値段: `wrangler.toml` の `AD_FREE_PRICE = "100"`。購入後に、買った人の対戦用アカウントに、広告削除が付く。**購入は、端末のキー(ブラウザの保存)に付く**ので、保存を消すと失われる(対戦ロビーの「引き継ぎコード」で、引き継げる)。
- **Stripe の実際の API との通しの確認は、一度もしていない**(署名の確認は、同じ手順で作った署名での確認まで)。**テストモードで、買う → 広告が消える、まで、必ず通しで確認**してから、本番の鍵に替える。
- 返品・キャンセル等の条件は、`legal/tokushoho.html` に書いてある(デジタルのため原則不可。反映されない・二重請求は、対応する)。

## 7. 広告
- 設計の全体: `docs/広告の設計.md`。コード: `js/ads.js`・`js/config.js`(`ads.provider`: `'none'`(初期値)/ `'mock'`(確認用)/ `'adsense'`)。
- **決まっている仕様**: バナーは、全画面(タイトル・NPC 戦・対戦)の下 / 全画面広告は、NPC 戦 3 回につき 1 回(結果画面から次へ進むとき)/ レート戦は、1日3回まで無料で、4回目からは、リワード広告を見ると+3回 / **広告削除を買うと、広告も、回数制限も、なくなる**。
- **有効化は、2か所をそろえる**: サーバーの `ADS_ENABLED = "1"` と、画面の `js/config.js` の `ads.provider = 'adsense'`(+ `client`・`bannerSlot`)。**片方だけだと、回数制限がかからない**(広告が出せないのに、見ろと言って遊べなくするのを防ぐため)。
- **注意(重要)**: いまは、「広告」と「回数制限」が、**1つのスイッチ**(`ADS_ENABLED`)につながっている。**リワード広告が承認される前に `ADS_ENABLED = "1"` にすると、4回目から、遊べなくなる**。バナー・全画面だけを、先に出したいなら、**回数制限を別のスイッチに分ける変更が、要る**(Claude Code に、頼んでほしい)。
- **AdSense の申請**: 公開済みのサイト(+ `legal/` の3ページ)が前提。全画面広告・リワード(H5 ゲーム広告の Ad Placement API)は、**別に申込みと審査**(承認は、保証されない)。`js/ads.js` の `adsense` の出し元(バナー・`adBreak`)は、**公開されている仕様の知識で書いただけで、本物では、一度も試していない**。承認後に、本物で確認が要る。
- **ポリシーの懸念**: バナーが、手札のカードと近い(8px)。AdSense は、ゲームの操作ボタンの近くの広告(誤クリックを誘う配置)を、禁じている。警告が出たら、**戦闘中だけ、バナーを隠す**(`ads.js` の `mountBanner`)。
- **広告を有効にするとき**: プライバシーポリシー(広告の外部送信の説明)と、`legal/` の**最終更新日**を、更新する。外部送信の公表の義務に合わせた表は、すでに入っている。
- 収益は、少額になる見込み(ゲームは、単価が低めの層。AdSense は、一定額に達するまで、支払われない)。数字は、確認できていない。

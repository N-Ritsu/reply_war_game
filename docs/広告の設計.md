# 広告と、広告削除の設計

2026-11-08 に追加。**広告は、初期状態では、すべて無効**(`js/config.js` の `ads.provider = 'none'`、サーバーの `ADS_ENABLED = "0"`)。公開して、広告会社の審査が通ってから、有効にする。

## 1. ユーザーが決めたこと
| 項目 | 内容 |
|---|---|
| バナー広告 | **全画面(タイトル・NPC 戦・対戦)の、いちばん下**に出す。 |
| 全画面広告 | **NPC 戦 3 回につき 1 回**。 |
| レート戦の回数 | **1日3回まで無料**。4回目からは、**リワード広告を見る**必要がある。**1回見ると、3回できる**。 |
| 広告削除 | **100円**で販売する。 |

## 2. 私が決めたこと(依頼になかった部分)
- **広告削除を買うと、バナー・全画面広告に加えて、レート戦の回数制限もなくなる**。リワード広告が出せない人に、広告を見ろとは言えないため。
- **回数は、「対戦が組まれたとき」に1回数える**(相手が人でも、ボットでも)。探すのを取り消したときは、数えない。1日の切り替わりは、**日本時間の 0:00**。
- **リワードで増やせるのは、無料の回数を使い切ったときだけ**(貯めておくことはできない)。見たと認める最短の時間は 5 秒(`REWARD_MIN_MS`)。
- **NPC 戦の数え方**: 勝っても負けても、結果画面が出たら1回。途中でやめた分は数えない。全画面広告は、結果画面から、「もう一回」「次の相手へ」「相手を選びなおす」を押したときに出る(試合の最中には出ない)。数えた回数は、ブラウザに保存される(開き直しても続く)。
- **広告の設定がないとき(`none`)は、回数制限もかけない**(広告が出せないのに、見ろと言って遊べなくするのを防ぐ)。サーバー側は `ADS_ENABLED`、画面側は `ads.provider` の、**両方を有効にしたときだけ**、制限がかかる。
- 購入は、**この端末の対戦用アカウント(端末のキー)に付く**。ブラウザの保存を消すと失われるので、**「引き継ぎコード」**(対戦ロビーの下)で、別の端末や、保存を消したあとに、引き継げる。コードは、アカウントの合鍵なので、他人に教えない旨を、画面に書いた。

| `js/config.js` | `ads: { provider, client, bannerSlot, interstitialEvery, price }`。`?ads=mock` で、確認用の偽の広告(`&adms=ミリ秒`)。 |
| `index.html` / CSS | バナーは `#ad-banner`(画面の下に固定。ゲームの画面は、その分だけ縮む。PC 108px / 幅860px以下・高さ620px以下は 68px。ボタンとの間に 8px の余白)。 |
| サーバー `db.js` | `daily_plays`(1日の回数)・`entitlements`(広告削除)・`payments`(同じ支払いを2回数えない)。`quota` / `usePlay` / `addReward`。 |
| サーバー `lobby.js` | 入室(`hello`)の返事に、今日の状態(`quota`)を入れる。探す(`queue`)とき、回数がなければ `quota {need:'ad'}` を返して断る。`adstart` → `adend`(見始め・見終わり)で、リワードを認める。対戦が組まれたら、1回数える。 |
| サーバー `pay.js` | `POST /api/status`(広告削除か・今日の状態)/ `POST /api/checkout`(Stripe の支払いページを作る)/ `POST /api/stripe-webhook`(Stripe からの「支払い完了」の通知。**署名を確かめて**、広告削除を付ける)。 |
| `wrangler.toml` | `ADS_ENABLED` / `FREE_RATED_PER_DAY`(3)/ `REWARD_PLAYS`(3)/ `REWARD_MIN_MS`(5000)/ `AD_FREE_PRICE`(100)。決済の秘密の値は、ここに書かず、`wrangler secret` で入れる。 |

**広告削除を付けられるのは、サーバーが、署名つきの支払い完了の通知を受け取ったときだけ**。画面の `localStorage` を書き換えても、画面の広告が消えるだけで、レート戦の回数制限は、サーバーが数えているので、外れない。

## 4. 公開するときの手順(ユーザーの作業)
### 4-1. 先に、公開して、審査を受ける
1. 広告を無効のまま(初期状態)、公開する(`公開手順.md`)。
2. **広告会社の審査を受ける**。Google なら、AdSense(サイトの審査)。全画面広告・リワード広告(H5 ゲーム向けの Ad Placement API)は、**別に申し込み・審査がある**(承認は保証されない)。審査には、**プライバシーの説明・連絡先などの、サイトの体裁**が求められることが多い。
3. 承認されたら、`js/config.js` に、`provider: 'adsense'`、`client: 'ca-pub-…'`、`bannerSlot: '…'` を書く。

### 4-2. 決済(Stripe)を用意する
1. Stripe のアカウントを作り、本人確認・口座の登録をする。
2. ダッシュボードで、**Webhook の送り先**を、`https://<公開した URL>/api/stripe-webhook`、イベントを `checkout.session.completed`(コンビニ払いなど、あとから払う方法を使うなら、`checkout.session.async_payment_succeeded` も)にして作る。表示される**署名用の秘密(whsec_…)**を控える。
3. 秘密の値を、Worker に入れる(画面には出ない):
```bash
cd server
npx wrangler secret put STRIPE_SECRET_KEY        # Stripe の秘密鍵(sk_…)。最初は、テスト用の鍵で
npx wrangler secret put STRIPE_WEBHOOK_SECRET    # 上の whsec_…
```
4. **最初は、Stripe のテストモードで、買う → 広告が消える、まで通して確かめる**(テスト用のカード番号は、Stripe のドキュメントにある)。確かめてから、本番の鍵に替える。

### 4-3. 広告を有効にする
1. `server/wrangler.toml` の `ADS_ENABLED = "1"`。
2. `js/config.js` の `ads.provider` を設定(上の 4-1)。
3. 新しい表を作る: `cd server && npm run db:remote`(すでに公開している場合。`daily_plays`・`entitlements`・`payments`)。
4. `./scripts/build.sh` → `cd server && npm run deploy`。

### 4-4. 法律・規約まわり(私は法律の専門家ではない。公開前に、確認を)
- **販売する場合の表示**: 有料で販売するので、**特定商取引法に基づく表記**(事業者名・連絡先・価格・支払い方法・返品の扱いなど)のページが要る(個人でも、販売業者に当たる)。価格は、税込みの総額を表示する。
- **広告・解析のための外部送信**: 広告のタグが、利用者の情報を外部(広告会社)に送る場合、**どの情報が・誰に送られるかを、公表する**義務がある(電気通信事業法の外部送信規律)。**プライバシーポリシーに書く**。EU など、同意の取得が要る地域に向けるなら、同意のバナー(CMP)も要る。
- **対戦の記録の利用**: 対戦の記録を、ほかのプレイヤーと対戦するボットの元に使うことを、規約・プライバシーポリシーに書く(`対戦設計.md`)。
- **決済会社の手数料**がかかる(率は、Stripe の公式ページで確認)。100円だと、手数料の割合が相対的に大きくなる。
- 広告のポリシー: **AdSense は、ゲームの操作ボタンの近くに広告を置くこと(誤クリックを誘う配置)を禁じている**(下の 5)。

## 5. 気をつけること・未確認のこと
- **バナーは、全画面に出す(ユーザー指定)ので、対戦・NPC 戦の最中にも出る**。このゲームは、連打・クリックが多く、**手札のカードと、バナーが近い**(間に 8px の余白を取っただけ)。AdSense のポリシーで、「誤クリックを誘う配置」と判断されると、**警告や、アカウントの停止**になりうる。実際に付けて、警告が出たら、**戦闘中は、バナーを隠す**(`ads.js` の `mountBanner` を、画面ごとに切り替える)ことを、おすすめする。
- **本物の広告・本物の決済は、一度も試していない**。確かめたのは、ローカルでの、偽の広告(`mock`)と、確認用の購入(`PAYMENT_MODE=mock`)、署名つきの通知(同じ手順で作った署名)まで。`adsense` の出し元(バナー・全画面・リワード)の、Google の API の呼び方(`adBreak`)は、公開されている仕様の知識で書いた。**審査と、本物での確認が要る**。
- **リワード広告を見たかどうかは、サーバーでは確かめきれない**(見始めてから 5 秒たったか、までしか確かめていない)。プログラムで、見ずに「見た」と送ることは、できる。Google の広告サーバー側の確認(AdMob のアプリ向けにはある)は、ウェブ向けには、使えない見込み。
- **1人が、複数のアカウントを作ると、無料の回数を増やせる**(アカウントは、端末のキーだけ)。
- 広告削除の購入は、**端末のキーに付く**。引き継ぎコードを控えていない人が、ブラウザの保存を消すと、失う。サポートの方針(再付与するか)を、決めておく必要がある。
- 全画面広告・リワード広告の表示中に、BGM・効果音は、止めていない(`sound` の設定だけ渡している)。
- 単価: **日本のブラウザゲームの信頼できる相場は、確認できなかった**(`history/2026-11-05.md` の追記28)。実測で見る。

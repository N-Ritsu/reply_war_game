# 設計メモ

## 1. 構成

NPC 戦は、すべてブラウザで動く静的ファイル。サーバーも、ビルドも、ログインも使わない。
`index.html` を直接開いても(`file://`)、静的サーバーから配っても動く。
**プレイヤー対戦(レート戦)だけ**、サーバー(Cloudflare Workers)を使う。詳しくは [対戦設計.md](対戦設計.md)。サーバーがなくても、ボット相手の練習は動く。

```
index.html          画面の骨組み(スクリプトは通常の <script> で読み込む)
css/style.css       見た目
js/data.js          データ: カード・NPC・台詞・弾幕のコメント(ここに足すだけで増やせる)
js/typing.js        リアルモードのローマ字入力の判定(DOM なし)
js/engine.js        ゲームの仕組み(DOM なし。時間と乱数も状態の中)
js/audio.js         効果音と BGM(WebAudio で合成。音のファイルなし)
js/npcview.js       奥の NPC(SVG)と、顔アイコン
js/ui.js            画面の制御。engine の「出来事(events)」を見て、見た目と音を動かす。対戦用に部品(RW.UIKit)を公開する
js/pvp.js           プレイヤー対戦のルール・Elo・練習用のボット(DOM なし。ブラウザとサーバーで同じものを動かす)
js/net.js           対戦サーバーとの WebSocket(ロビー・部屋・ランキング。サーバーの自動検出)
js/pvpui.js         対戦の画面(ロビー・隙みせのボタン・手札/打ち込み・ログ・結果)
js/config.js        環境ごとの設定(対戦サーバーの URL。公開のとき書き換える)
server/             対戦サーバー(Workers + Durable Objects + D1)。build-game.js が、js/ のルールをサーバー用にまとめる
tests/run.js        仕組みのテスト(Node で実行。tests/pvp.js の対戦のテストも呼ぶ)
scripts/pvp-sim.js  対戦のバランスの自動対戦
scripts/build.sh    配布用の public/ を作り、入れ忘れを確かめる
```

- **データ・仕組み・画面を分ける**(前回の教訓6): カードや NPC は `data.js` に1項目足すだけで増える。仕組みのテストは、画面なしで動かせる。
- **スクリプトを ES モジュールにしない**: `file://` で開くと、ブラウザがモジュールの読み込みを止めるため。各ファイルは `RW` という名前空間に登録し、Node では `module.exports` でも取り出せる。

## 2. ゲームの仕組み(engine.js)

### 2-1. 状態と時間
- `state.t`(ミリ秒)を `step(state, dt)` で進める。乱数は `state.rng` に持つので、同じ `seed` なら同じ展開になる(前回の教訓6)。URL に `?seed=123` を付けると再現できる。
- 画面へは `state.events` に出来事を積んで伝える。主な出来事: `tell`(前兆)・`npcPost`・`play`・`ignored`・`typoRisk`・`typoSaved`・`typoHit`・`slotReady`・`reload`・`end`。
- 隠しパラメータは持たない。

### 2-2. NPC のレス
1. レスを出した直後に、**次のレスの種類**と**時刻**を決める(`scheduleNext`)。次のレスまでの合計時間は、NPC ごとの間隔に、種類ごとの倍率をかけたもの。
2. 合計時間のうち、後ろの一定の割合が**入力中**(`tell`)。この間、画面には「入力中」の吹き出しと「入力待ち ○秒」が出て、奥の NPC が動く。**長文は入力が長く、短文は短い**(下の表)。
3. 時間になると `npcPost`。返信待ちの一覧(`pending`)に入り、猶予の時間が始まる。
4. まだ返していないレスの猶予を過ぎると放置(`ignored`)。支持率が下がり、コンボが切れる。返したレスは放置にならない。
5. 短文連打は、3つを0.48秒おきに続けて出す(間は入力中の表示なし)。

| レスの種類 | 合計時間の倍率 | 入力にかかる割合 | 平均の入力時間(テストの実測) |
|---|---|---|---|
| 長文 | 1.2 | 75% | 約3.4秒 |
| 感情論 | 1.0 | 50% | 約1.6秒 |
| ブーメラン | 0.95 | 45% | 約1.3秒 |
| 論点ずらし | 0.9 | 40% | 約1.3秒 |
| 短文連打 | 0.75 | 30% | 約0.7秒 |
| 自演 | 1.0 | 50% | — |

### 2-2a. 2つのモード(2026-11-06 に変更)
| | 爽快モード | リアルモード(`state.free`) |
|---|---|---|
| 攻撃の方法 | ボタン1つ(1〜5キー・クリック・タップ) | 言葉をローマ字で打ち込んで Enter |
| 使える言葉 | **手札の5枚だけ**(使うと0.15秒で補充。「↻」で引き直し 約1秒) | **全部**(自演乙を除く27個。手札・補充・引き直しはない) |
| 腕の見せどころ | 5枚のやりくり(引き直しのタイミング) | 見極めと打ち込みの速さ・正確さ。誤字の扱い |
| 威力 | カードの威力どおり | 長い言葉ほど上がる(× 0.85〜1.3) |
| 相手のメンタル | 100% | 70% |
| 相手のレスの間隔 / 返信の猶予 | 標準 | 間隔 × 1.35 / 猶予 × 1.8 |
| 同じ言葉 | (手札が入れ替わるので対象外) | 同じレスに2回目から効かない |

- エンジンでは、`play`(手札のスロットで攻撃)と `playFree`(言葉を直接渡して攻撃)の2つの入り口が、同じ `attack` を使う。ダメージ・詰め・必死度・追撃・待たせ煽りなどの規則は、2つのモードで共通。
- 爽快モードのバランス(手札が5枚で、引き直しに待ちがある)と、リアルモードのバランス(打ち込みに時間がかかる)は、別々に自動プレイで測っている(下の 2-4)。

### 2-2c. レスが重なったときと、同じ言葉のルール(2026-11-06)
- **前のレスの猶予を縮める(`prev` / `graceMs`)**: 新しいレスが来た時点で、まだ返していない前のレスの期限を `s.t + prevGraceMs(2200ms。リアルは × 1.8)` まで早める(元の期限のほうが短ければそのまま)。猶予バーは、縮めた時点からの残りで減る(`graceMs`)。これで「どちらが有効か」の混乱を避ける。判定(`targetFor`)の中身は変えていない。
- **画面の強調(ui.js)**: 返していない最新のレス(なければ、最後に返したレス)だけが `.target`(「◀ いま返す」「◀ 追撃OK」)。ほかの未返信は `.prev`(薄い・破線の枠・「前のレス」)。手札は `E.counterTarget` で、効くレスの番号を「▶ No.○」と出し、最新のレス以外に当たるカードは `.recprev`(青)。スマホ幅では番号は隠す。
- **同じ言葉(リアルのみ)**: 各レスと、入力待ち(`state.incoming`)に `used` の表を持つ。`attack` の冒頭で、`state.free` かつ表に同じカードがあれば `outcome = 'dup'` として、ダメージ・コンボ・必死度・詰め・追撃数のどれも変えずに返す(`stats.repeats` だけ増える)。`isRepeat(state, card)` を、画面(一覧の「済」)と、攻撃一覧の説明に使う。

### 2-2b. 攻撃のルール(2026-11-05 に変更)
- **何回でも攻撃できる**: 返したレスは、次の相手のレスが来るか、猶予が切れるまで、追撃を受け付ける。
- **攻撃の向かう先**(`targetFor`): **撃ったカードが効くレスに当たる**。前のレスの猶予が残ったまま次のレスが来る(返信待ちが2〜3件になる)ことがあるため、「一番古いレス」に固定すると、最新のレスに効くカードが古いレスへの攻撃扱いで外れになっていた(不具合。修正済み)。
  1. まだ返していないレスのうち、そのカードが効くもの(いちばん古いもの)
  2. 返し終えたレスで、効くもの(追撃)
  3. 効くレスがなければ外れ。**まだ返していない一番新しいレス**への外れとして扱う(通知の種類も、最新のレスのもの)。なければ、直前に返したレス
  - いなすカードは、まだ返していない一番古いレス(なければ直前に返したレス)。
  - 画面の「効くカードが光る」は `counterTarget`(効くレスがあるカードだけ)で決める。「◀ 返信待ち」は、返せるレスすべてに付く。
- **追撃の威力**: 1発目×1 / 2発目×0.75 / 3発目×0.6 / 4発目以降×0.5。効かないカードを撃てば、追撃でも外れ。
- **必死度**(`state.rush`): 攻撃で+1(いなすカードは+0.4)、1秒で-0.8。**限界(4)を超えると反撃**(`fireRush`): 支持率 -10、コンボ切れ、相手の「必死で草」などのレスが出て、自分に飛んでくる。反撃のあと、必死度は0に戻る。
- **とどめの場面**(相手のメンタル25%以下): 限界が7に、減りが1秒あたり1.5に上がる。とどめを刺した攻撃は反撃されない。
- **待たせ煽り**(`card.wait`): 相手が入力中のとき、待ち時間が `wait.min` 以上なら成功。威力 = 威力 × コンボ倍率 × `waitMul(待ち時間)`。`waitMul(ms) = min(waitMulMax, waitMulBase × 2 ^ ((ms − waitMinMs) / waitDoubleMs))`(`CFG`: 2000 / 0.5 / 1200ms / 上限4)。指数関数なので、2秒 0.5 → 3.2秒 1 → 4.4秒 2 → 5.6秒 4(上限)と、後ろほど急に伸びる。`wait.min` は3枚とも 2000(相手の入力が2秒以上)。画面は `E.waitMul` で、入力待ちの横に「煽り ×○」を出す。早すぎる・入力していないときは外れ。返信待ちのレスは消費しない。コンボは増える。
- 即レスのボーナスは、1発目だけ。
- **返すレスがないときの攻撃は外れ**: 相手が入力中、またはまだ何も書き込んでいないとき(`targetFor` が `null`)に、効くレスのない攻撃カードを使うと、外れ(`noPost`、入力中なら `typingNow`)。以前は「追い打ち」として威力35%のダメージが入り、外れにならなかった(入力中の長文に「早口」が通る不具合)。例外は、入力待ちを突くカード(入力中だけ効く)と、いなすカード(外れない・威力小)。
- **詰め**(`firePunish`): 的外れな攻撃(外れ・早すぎる待たせ煽り・入力していない相手への待たせ煽り)のあと、相手が `RW.PUNISH[相手のid]` の台詞で、こちらのレスにアンカーを付けて詰める。支持率 -6(`punishHit`)。跳ね返りのダメージとは別。支持率が0になれば負け。
- **連続攻撃のしやすさ**: 使ったカードは0.15秒で補充される。補充のカードは、いま攻撃中のレスのタイプに効くものを2.4倍出やすくする(`chainBias`)。ヒットストップは最大0.07秒。

### 2-2c. 数値(engine.js の `CFG` と data.js)
| 項目 | 値 |
|---|---|
| 手札 | 5枚 |
| 補充 / 引き直しの待ち | 0.15秒 / 1.0秒 |
| 返信の猶予(基準) | 長文5.4秒・感情論3.8秒・ブーメラン4.2秒・論点ずらし4.2秒・短文連打3.2秒・自演4.2秒(NPC ごとに倍率) |
| 外したとき | 跳ね返りで支持率 -7〜-8(カードごと)、コンボ切れ。さらに**詰め**で -6 |

| いなす | ダメージ2〜3、支持率 +1(1発目のみ)、コンボは維持、必死度 +0.4 |

| 誤字のつっこみ | 猶予2.4秒、支持率 -12、コンボ切れ |

得点 = 最大コンボ×150 + 支持率×20 + 即レス×80 + (60秒 - 時間)/40 - ミス×150 - 誤字ツッコミ×200 - スルー×60 - 反撃された×150。

### 2-3. 手札の配り方
- 同じカードは手札に重ならない。
- その NPC がよく出す種類に効くカードを出やすくし、**その NPC がまず出さない種類にしか効かないカードは出にくくする**(重み×0.4。手札に死にカードが溜まりにくくする)。
- 待たせ煽りのカードは、長文をよく出す NPC との戦いで多く配る(長文の割合に応じて重みを変える)。
- 使ったカードの**補充**だけは、いま攻撃中のレス(まだ返していない一番古いレス、なければ直前に返したレス)に効くカードを2.4倍出やすくする。最初の配りには効かない。
- 「自演乙」は、自演する NPC(ボス)との戦いでだけ配る。

### 2-4. 「買ってすぐ売る」穴がないことの確認(前回の教訓6)
- 外し続けると必ず損をする(テストに入れた)。
- 何もしないと負ける。でたらめに連打しても勝てない(20回中0回)。
- 効くカードを**間をあけずに**撃ち続けても、必死度の反撃で支持率を削られ、勝ちにくい(20回中9回。必死度を見ながら追撃・待たせ煽りを使う自動プレイは、全 NPC に 20/20)。
- リアルモードは、打ち込み速度のある自動プレイ(効く言葉のうち、威力×倍率÷(打つ時間)が最大のものを選ぶ)で測る。(間隔 × 1.35・猶予 × 1.8・メンタル × 0.7 にした後)**打つのが速い人(1秒に3.2文字)**は、全 NPC に 18〜20/20 で勝てる。**普通の速さの人(2.2文字)**は、10〜20/20。リアルモードは「上級者向け」。この自動プレイは追撃・待たせ煽り・誤字の立て直しをしないので、人間はもう少し有利と見ている。
- 追い打ちは威力が小さく、コンボを増やせない。

## 3. リアルモードの入力(typing.js)

- カードの読みを、かな1文字ずつの「打ち方の候補」に分ける。「し=si/shi」「ち=ti/chi」「つ=tu/tsu」「ふ=hu/fu」「じ=zi/ji」、拗音(sya/sha など)、「っ」(子音を重ねる / xtu)、「ん」(n / nn / xn。次が母音・な行・や行のときは nn が必要)に対応。
- **全部の言葉**(リアルモードの `state.pool`。手札はない)を同時に追う。打つうちに候補が絞られ、最初の数文字で、どの言葉を打っているかが決まる。`Session` の `slot` は、言葉の一覧の番号。
- **誤字**: 候補に合わないキーを打つと、その位置の1文字を飛ばして先へ進み、誤字として数える。Backspace で1文字ずつ戻せる(誤字も戻る)。
- 打ち終わっても自動では送らない。**Enter** で送信する(「ッターン!」)。打ち終わる前の Enter は無視する。
- 誤字つきで送ると、レスの本文の数文字が、赤い波線の誤字になる。
- キーは `event.code`(物理キー)で読むので、IME がオンでも、日本語配列でも判定できる。QWERTY 配列を前提にする(Dvorak などは未対応)。

## 4. 画面(ui.js / style.css / npcview.js)

### 4-1. デザインの方針(2026-11-05 に全面的に作り直し、2026-11-06 に作り込みを足した)
- **方針**: リアルさよりも、**爽快感と分かりやすさ**。最初の版は「本物の掲示板らしさ」を優先して地味にしすぎ、見づらかった(ユーザーの指摘)。その後、「キャラや UI が簡素」という指摘を受け、**線と塗り分けの約束事は崩さずに、情報量と質感を増やした**。
- **見た目**: マンガのコマ。太い輪郭(3px)・原色のベタ塗り・かたい影。アリーナ(奥の相手)は黄色の集中線とハーフトーン、スポットライトと床の舞台、隅の飾り(角の括弧)、漂う「草」。ほかは暗い紺で静かにして、アリーナとダメージの演出へ視線を集める。
- **質感(2026-11-06)**: パネルに、ハーフトーン・上の光・下の影・内側の縁。ゲージ(支持率・メンタル)に、目盛りと上の光沢。ボタンに光沢。吹き出しに、しっぽ(インク縁つき)と淡い陰影。
- **情報(2026-11-06)**: レスの種類ごとの**アイコン**(長文=紙・感情論=爆発・ブーメラン=曲がる刃・論点ずらし=矢印・短文連打=吹き出し・自演=2人・待たせ煽り=砂時計・いなす=盾・追い詰めたとき=ひび割れた心・複数=星)。カードに、アイコンと透かし絵と**威力の点**(5段階)。相手の名札に、**難しさの星**と**得意なレスの札**(上位3つ)。相手の一覧に、得意なレスの札と**ランクのメダル**。結果に、メダルの光、相手の表情(負けて壊れた顔)、紙吹雪(負けたときは灰色の「草」が降る)。
- **色**: 輪郭 `#0d0820` / 地 `#17112e` / パネル `#2a2060` / アリーナ `#ffcf33` / 相手=赤 `#e3243a` / 自分=青 `#1668e8` / 強調 `#ffe14d`。陰影は紫がかった半透明 `rgba(70,20,70,.22)`、モニターの照り返しは `#8fbaff`。
- **書体**: 日本語のゴシック(ヒラギノ角ゴ・游ゴシック・Noto Sans JP)。太字と斜体で勢いを出す。数字と見出しには白い文字に太い黒縁と、色つきの影。外部フォントは使わない。
- 避けたもの: クリーム色に赤茶、黒地に蛍光色、同じ見た目のカードを均一に並べる配置、グラデーションと光沢だらけの面、リアルな絵柄への寄せ方。
- 見直したこと: (1)最初の版は、掲示板の再現を優先して素っ気なくした結果、見づらく地味だった。(2)作り込みでは、「光沢やグラデーションを全面に足す」案を採らず、線の太さと塗り分けをそろえたまま情報量を増やす方針にした。(3)見せ場は引き続き NPC とダメージの演出に集中させ、飾りは静かに抑えた。

### 4-2. 画面の構成
```
┌ HUD: [自分の顔]━━ 観衆支持率(青=自分 / 赤=相手)━━[相手の顔]  ♪ Ⅱ ┐
├ アリーナ(奥の相手)────────────┬ ログ(チャット風)────────────┤
│  COMBO(左上)  前兆の札(右上)   │  [相手の顔] 白い吹き出し(左)     │
│  相手(大きく)                  │         青い吹き出し [自分の顔]  │
│  名札+メンタルのゲージ(真下)   │  ……返信待ちは黄色い枠            │
├ 手札(爽快: 5枚。効くカードは黄色く光る)/ 言葉の一覧(リアル: 全部の言葉)┤
```
- 画面が狭い(860px以下)ときは、HUD → アリーナ → ログ → 手札(2列)の縦並びにする。
- **誰が打ったか**: 相手=左・赤い名札・白い吹き出し・相手の顔 / 自分=右・青い名札・青い吹き出し・自分の顔(サングラスの青いパーカー)/ 自演レス=ピンクの名札・「?」の顔。
- **いま返す相手**: 返信待ちの先頭に、黄色い枠と「◀ 返信待ち」を付ける。猶予の残りは、吹き出しの下の線で見せる(残り少ないと赤く震える)。
- **レスの種類**は、札(ヒントあり)と、書き方の両方で分かる。長文=小さい字で太い枠 / 感情論=赤い太字が震える / ブーメラン=紫の波線 / 論点ずらし=斜体 / 短文連打=大きな字。
- **カード**: 上の帯に「○○に効く」(種類ごとの色)。ヒントありのときは、**いま効くカードが黄色く光って跳ねる**。ヒントなしでは、帯は無地になる。
- 相手が入力中(前兆)のときは、ログの下に、相手の顔つきの「…」の吹き出しが出る。

### 4-2b. 手札の操作(2026-11-06 に直した「押しても攻撃できない」)
- **原因(実ブラウザで再現)**: 攻撃を起こすのは、カードの中の本文のボタン(`.card-main`)だけだった。カードの上の帯・番号・アイコンは、ボタンの外にある別の要素なので、押しても何も起きなかった(反応する範囲は、カードの下の7割ほど)。また、補充中(空き)のスロットを押すと、黙って無視されるので、「押したのに攻撃できない」と感じた。
- **修正**: (1)クリックを**カード全体**で受ける(「↻ 引き直し」だけ別)。帯・番号・アイコン・威力の点・透かし絵には `pointer-events: none` を付け、クリックが下のカードに届くようにした。空きのカードの本文ボタンにも `pointer-events: none` を付け、クリックがカードに届くようにした(`disabled` だと、クリックが親に届かない)。(2)補充を 0.25秒 → **0.15秒**に。(3)補充中のスロットを押したら、スロットを揺らして小さく鳴らす(`nope`)。(4)ホバーと光る札を、動かす演出(上へ浮く・上下に弾む)から、影と光を変える演出に変えた。動くと、押す前後で当たり判定がずれて、端を押したクリックが取りこぼされる。
- **確認**: ブラウザで、カードの6か所(帯・番号・アイコン・本文・威力の点・右下の引き直し以外)を押して、すべて攻撃になること。別々の3枚・5枚を0.06〜0.1秒おきに押して、すべて攻撃になること。同じ場所を0.17秒おきに4回押して4回とも攻撃になること(カードは毎回入れ替わる)。補充中を押すと無視され、揺れる合図が出ること。

### 4-3. ダメージの演出(「こちらの攻撃が効いている」を大きく見せる)
特攻のときの流れ(合計 約0.5秒):
1. カードの文字が、手札から相手へ飛んでいく(約0.23秒)。
2. 着弾: 爆発・集中線・輪・斬撃(大ダメージとコンボ5以上は3本)/ **ヒットストップ**(時間が一瞬止まる。ダメージが大きいほど長い)/ 相手が白く光ってのけぞる / 画面が揺れる(大ダメージは強く)。
3. 巨大なダメージ数字(ダメージが大きいほど大きい)と、「特攻！」「即レス！」の札、コンボ数。
4. メンタルのゲージが減り、白い残像が遅れて追いかける。数字も減る。コンボは左上に大きく出て、増えるたびに弾む。
- **外したとき**: カードが相手に当たって**跳ね返され**(灰色の爆発と「効かない！」)、そのまま**自分の顔に当たる**。支持率の減りは、当たるまで表示を保つ。自分の顔が目を回して揺れる。
- **スルーされたとき・誤字をつつかれたとき**: 相手のレスが飛んできて、自分の顔に当たる。
- **連発の反撃**: 「連発しすぎ！」と、相手の「必死で草」などのレスが飛んできて、自分の顔に当たる(支持率 -10)。必死度のゲージが限界の74%を超えると、ゲージが赤く震え、「連発しすぎ！あと1発で反撃される」と知らせる。
- **追撃**: 返したレスには「◀ 追撃OK」と青い猶予の線が付く。追撃は「追撃！」の青い札で、通常の特攻と見分けられる。
- **待たせ煽り**: 「待たせ煽り！」の青い札と、「○.○秒待たせた」が出る。待たせるほどダメージ数字が大きくなる(指数関数。「入力待ち ○秒  煽り ×○」で倍率を出し、1.5倍以上で黄色くなる)。
- **とどめの場面**: 「とどめのチャンス！」の札と、金色に光る必死度のゲージ(「とどめラッシュ！連発OK」)。
- 演出の大きさは、アリーナの大きさに合わせて縮める(スマホでも画面から溢れない)。
- 実装: 演出は最前面の `#fx` に重ねる。飛翔は Web Animations API。エンジンの状態は、押した瞬間に更新される。画面だけを着弾まで遅らせる(`mHold`・`sHold` で、ゲージの表示を保つ)。

### 4-4. 奥の人物(npcview.js)
- **2026-11-06 に、人物を土台から描き直した**(ユーザーの指摘: 「図形を貼り付けたような安っぽい見た目。完全にキャラクターっぽいデザインに」)。それまでは、円と楕円の部品を貼り合わせた絵だった。今は、**イラストとして描いた人物**を、SVG の JS で組み立てる(1体 約860ノード・約60KB・構築 約3ms)。部屋・机の小物は、そのまま。
- 見た目は4つの属性で切り替える(`data-face` 顔・`data-arms` 腕・`data-pose` 動き・`data-att` 普段の顔つき)。CSS は `style.css` の「人物の描画」。
- **線と色**: 線は真っ黒ではなく、**深い紫**(`#1b1030`)。肌・髪・服の色から、**明るい面・基本・影・暗部**(影は少し紫に寄せる)を計算して、CSS の変数(`--skin-hi` など)で塗る。面は「放射状のグラデーション + セル影(右頬・生え際の落ち影・あごの下)+ 艶」。**モニターの青い照り返し**が、肩・服の縁と、胸元から顔にかけての淡い光に入る(光は楕円のグラデーションで、境目が出ない)。
- **顔**: あごのある顔の形(丸・シャープ・四角の3種類)・耳・首・鼻・頬の赤み・頬のハイライト。人ごとに、目の大きさ・つり目/たれ目・眉の太さ・顔の形を変える(`ES`。服の種類で決まる)。ぼくちゃんだけ、頭を少し大きくする(子どもらしさ)。
- **目**: **まぶたの形(開き・つり目・たれ目)で切り抜いた中**に、白目・まぶたの影・**虹彩(上が暗く下が明るいグラデーション)**・虹彩の縁・瞳孔・**2つのハイライト**を置く。上まぶたの太い線・まつ毛の跳ね・二重の線・下まぶたの細い線。感情ごとに、まぶたの高さ・つり具合・瞳の大きさ・視線を変える(パニックは瞳が縮み、白目が出る)。まばたきあり。壊れた顔は**ぐるぐる目**。
- **眉**: **先の細い塗りの形**(内側が太く、外側が細い)。気持ちで、角度・高さ・太さが変わる(怒りはV字・困りは八の字・ひねくれは片方だけ上げる)。
- **口**: 一文字・への字・笑顔・ニヤリ(えくぼ)・不気味な笑み・食いしばる歯・大笑い・怒鳴り(上下の歯と舌)・「お」・波線・舌出し・ウインクつき。
- **髪(6人それぞれ)**: フード(深くかぶり、前髪だけが出る)/ なでつけ(分け目・艶)/ ツンツン(大きな束・先の艶)/ キャップ(つばが正面・縫い目・ロゴ)/ ロング + ネコ耳(片目を隠す前髪・ヘアピン)/ ぼさぼさ(前髪がメガネにかかる)。すべて、**艶(ハイライト)・毛束の線・おでこへの落ち影**つき。
- **体・服(6種類 `outfit`)**: スウェット(フードの付け根・ひも)/ スーツ(白シャツ・ラペル・襟・ネクタイの柄)/ タンクトップ(素肌の胸・筋・金のチェーン)/ Tシャツ(星のプリント・リブ)/ セーター(編み目・鎖骨)/ ジャケット(立ち襟・ジッパー・赤いライン)。しわと影つき。
- **腕・手**: 上腕をからだに沿わせ、**ひじで曲げて**、前腕をキーボードへ(折れ線 + 丸い角)。輪郭・陰・艶の3層。指のある手。キーボードの上で動く(気持ちで速さが変わる)。ポーズ: 打つ・両手を上げる(深呼吸)・片手でお菓子・頭を抱える。
- **小物**: ヘッドセット・メガネ(丸 / 四角・反射)・マスク・目の下のクマ・絆創膏・そばかす・イヤホン・青筋。(傷は、何か分からないと指摘されて、描かないことにした。`scar` の特徴は、データには残っているが、描画しない)
- **部屋(6種類 `room`)・机の小物(6種類 `desk`)**: 変更なし。
- **普段の顔つき**(`look.att`): 根暗(`sullen`)/ 攻撃的(`aggro`)/ ひねくれ(`smug`)/ 生意気(`brat`)。余裕・拮抗のときだけ、この顔に置き換わる(焦り以降は共通の顔)。姿勢も変わる。
- **特徴**(`look.traits`): `hood` `eyebags` `bangs` `eyecover` `scar` `spiky` `headset` `bandage` `piercing` `cans` `veins` `mask` `chain` `earbuds` `catears`(髪型は、服の種類で決まる)。
- 気持ち(メンタルの割合で決まる): 余裕(75%超)→ 拮抗 → 焦り(45%以下)→ 発狂(15%以下)。タイピングの手の速さも変わる。
- **顔アイコン**(HUD・ログ・相手の一覧・VS 画面・結果・対戦): 頭だけの**軽い SVG**(1つの表情だけを持つ。約6KB。同じ表情はキャッシュする)。**キャッシュした SVG を何か所にも置くと、中の id(グラデーション・切り抜き)が重なり、顔が塗られなくなった**ので、置くたびに `NV.reid` で id を付け直す。HUD と入力中の顔は、気持ちが変わるたびに作り直す。**自分**は、**AI で作った画像**(青い髪・ヘッドホン・サングラス。`assets/player-cool|win|hurt.jpg`。384px・各 約30KB)で、`data-face`(cool / win / hurt)で切り替える。生成は `scripts/gen-character-icons.py`(Cloudflare Workers AI の FLUX.2 [klein] の参照画像つき編集)。**名無し**(自演・対戦相手)は、フードを深くかぶった顔のない人。
- 前兆: 入力が始まったとき、種類に応じた動きを**最初の約1.3秒だけ**する(あとは打ち込み続ける)。ヒントありのときは、アリーナの右上に「⚠ ○○が来る！」の札も出る。
- 論破されたら、台パン → コーヒーがこぼれる → フェードアウト。
- `prefers-reduced-motion` のときは、動きを止める(まばたき・湯気・光る帯・紙吹雪・スポットライトも止める)。

### 4-5. 弾幕
- アリーナの上、**名札・コンボ・ログ・手札の下**の層に流す。ログと手札のパネルは不透明で、名札は弾幕より手前にあるので、**ゲージと文字の読みやすさを損なわない**。
- 量: ふだんから流れる(1秒に約1つ)。コンボと相手の入力待ちで増え、最大で1秒に約10。特攻1回で 4 / 8 / 16 / 36 個(コンボ 0〜4 / 5〜9 / 10〜19 / 20以上)。
- 勝利・敗北の演出では、それぞれのカットインの**中**(帯と文字の間)に専用の層を作り、大量に流す。論破は約110個を3.5秒で流す。帯は透けさせて、後ろの弾幕が見えるようにした。

### 4-5b. 開始の演出と論破の演出
- **開始**: VS 画面(左=あなた・青、右=相手・赤。顔アイコンと名前、台詞の紹介)が斜めに滑り込む → ゴング(カーン！)→ 回る集中線・輪・白い斬撃・「カーン！」「BATTLE START!!」+ 画面の揺れと閃光 → 戦闘開始(合計約3.1秒。VS はクリック・タップで飛ばせる)。縦長の画面では「BATTLE / START!!」を2行に積む。
- **論破**: 画面幅の約9割(縦長の画面では縦組み)の「論破！」を、傾いた帯の上に叩きつける。回る集中線・3重の輪・揺れ・白い閃光。奥の相手は台パンして消える。結果の表示は約4.3秒後。
- 敗北: 動く煽りアスキーアートと、大量の煽り弾幕(約3.3秒後に結果)。

### 4-7. 効果音(audio.js)
音のファイルは使わず、WebAudio で合成する。飛んでいく音・着弾(ダメージが大きいほど重い)・跳ね返り・ゴング・VS・必死度の警告・とどめの合図などがある。**聞こえ方は、私の環境では確かめられない**(下の「未確認」を参照)。
- **フリー素材のサンプル(2026-11-08〜)**: 攻撃の音(種類ごとの発射・着弾)とゲーム開始の一部に、**効果音ラボ**の素材 9個を使う(隙みせを打つ = ショット / 引き直し = 手裏剣は、`SE_REPLACE`)。素材は無加工で `js/sfxdata.js` に埋め込み(`scripts/build-se.py`)、最初の操作のあとに読み込む(`audio.js` の `loadSamples`)。割り当ては `SE_MAP` / `SE_LAYER` / `SE_GAIN`。**読み込めなければ、従来の合成の音で鳴る**。API は `Sound.launch(種類)` / `Sound.hit(種類, ダメージ, コンボ)`。出典・規約・割り当て・守っていること(試聴ページを公開しない等)は、[効果音の素材.md](効果音の素材.md)。
- **失敗の記録**: 2026-11-07 に、攻撃の音・ゲーム開始の音を、合成で作り直したが、「ぷつぷつして、爽快感がない」と指摘され、全部、元に戻した(波形の数値で点検しても、聞こえの良さは、合成では保証できなかった)。そのため、聞こえ方が決まる部分は、録音された素材を使い、**選ぶのはユーザーの耳**とした。


### 4-8. BGM(audio.js の `Music`)
- 曲もすべて合成する。**16分音符のシーケンサー**で、少し先(0.2秒)まで音を予約しておく(画面が重くなっても途切れにくい)。曲の定義は、`TRACKS` に「テンポ・小節ごとのベース音・ドラムなどのパターン(16文字の文字列)・ギターのリフ・メロディ」を書くだけ。
- **ロック**(2026-11-06 に作り直した)。ギターは、のこぎり波を2本ずらして重ね、**ひずみ(WaveShaper のディストーション)→ 高音をまるめる**を通す。ギターのリフは、刻み(パームミュート。短く暗い音)・パワーコード(根音+5度+1オクターブ上)・高いアクセントの3種類。リードギターは、チョーキング(音程を持ち上げる)とビブラート付き。
- 5曲:

| 曲 | テンポ | 作り |
|---|---|---|
| タイトル(セレクト画面) | 140 BPM | ロックンロール。Em-C-D-Em。ギターの刻みとパワーコード、軽快なリード。 |
| 戦闘 | 176 BPM | ハードロック。Am-F-G-E。ギターが16分で刻む(ガロップ)。駆け上がるリード。 |
| ボス戦 | 188 BPM | メタル。Dm-B♭-C-A。半音で動くリフ。低くて重い。 |
| 勝利の結果 | 148 BPM | 明るいロック。C-F-G-C。 |
| 敗北の結果 | 76 BPM | 重く沈むバラード。Am-F-Em-Am。コードを長く伸ばす。 |

- **戦い感の出し方**: ギターの刻み / 小節の頭(4小節に1回と、盛り上がったときの3小節目)のシンバル / 4小節目の最後の1拍のスネアのロール(フィル)/ ベースの刻み / 8分で駆け上がるリード。
- **盛り上がり(3段階)**: ふだん=ドラム・ベース・ギターの刻み。コンボ2以上か相手が焦る=**パワーコードを伸ばす・リード・16分のハット**が加わる。コンボ6以上かとどめの場面=**アルペジオと2発目のキック**が加わる。とどめの場面は、テンポも7%上がる。
- 流れる場面: タイトル → (VS 画面は無音)→ ゴングの余韻のあと戦闘の曲 → 論破・敗北の演出中は止める → 結果で勝利/敗北の曲 → タイトルに戻ると、またタイトルの曲。一時停止では、音量が3割に下がる。
- **音量**: ブラウザのオフライン描画で、曲ごとに測定した。割れなし(ピーク約0.4〜0.5)。ひずんだギターの分だけ実効値が大きくなったので、出力を下げて調整した(BGM の出力 0.55)。盛り上がると実効値が上がる。
- ブラウザは、最初の操作があるまで音を出せない。最初のクリック・キー入力のあとから、タイトルの曲が流れ始める。
- 設定: 「音」(効果音と BGM をまとめて切る)と、「BGM」(BGM だけ切る)の2つのボタン。どちらも設定を保存する。

## 6. 既知の制約・やっていないこと
- NPC 戦の記録の保存は、ブラウザの中だけ。端末をまたいだ引き継ぎはない。レート戦の記録(レート・戦績・ランキング)は、サーバー(D1)に保存するが、アカウントは端末のキーだけで、別の端末には引き継げない([対戦設計.md](対戦設計.md) の「限界」)。
- CSP(セキュリティの見出し)は、`file://` で動かせるよう、HTML には書いていない。公開するときは、配信側の設定で付ける(`公開手順.md`)。`style-src` は、SVG に付けた色の指定のため `'unsafe-inline'` が要る。
- 画面の幅が狭すぎる(320px 未満)ときの確認はしていない。
- 音は、聞こえ方を確かめていない。
- キー配列は QWERTY 前提。
